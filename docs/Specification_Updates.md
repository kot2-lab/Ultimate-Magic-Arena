# Ultimate Magic Arena — 追加仕様更新記録

このファイルは、`MASTER_GUIDE.md`に具体値が定義されていなかった項目と、Ver.1.0で実装・決定した内容を記録する。元の`MASTER_GUIDE.md`は変更せず保持する。数値の調整は本ファイルと次版の完全版ガイドに追記し、過去の要件を削除しない。

## Ver.1.0（2026-10-14）

### リリース範囲

- Ver.1.0はブラウザーで遊ぶオフラインCPU対戦版とする。アカウント、オンライン対戦、ランキング、クラウド保存は含めず、ロードマップ上のVer.2.0で扱う。
- プレイヤー進行状況と設定はブラウザーの`localStorage`へ保存する。設定画面からJSONバックアップを書き出せる。
- `release/ver-1.0`ブランチをGitHub Pagesから公開する。公開ゲームURLは`https://kot2-lab.github.io/Ultimate-Magic-Arena/`。GitHub Actionsが同ブランチへの更新時にデプロイする。
- 元のVer.0.3.1をベースラインとして保持する。タイトル画面のSTART操作を装飾が妨げない仕様（装飾要素を操作対象から除外）を維持する。
- UIは魔法・闘技場を題材にした落ち着いたファンタジー調とし、サイバー／ネオン表現は採用しない。PC・タブレット・スマートフォンに対応し、動きを抑える設定を用意する。

### 初期プレイヤー・成長

- 初期値：レベル1、EXP 0、HP 100/100、MP 30/70、MP回復5/ターン、レーティング1000。
- レベル上限は999。次レベルに必要なEXPは`floor(80 + level × 22 + level^1.16 × 4)`。
- レベルアップごとに最大HP +5、最大MP +2。5レベルごとにMP回復 +1、10レベルごとに追加で最大HP +10、最大MP +5。レベルアップ時はHP・MPを全回復する。
- 戦闘参加EXPは10〜30。勝利時は追加で100〜120。格上CPUの場合は追加ボーナス（基礎5〜10、勝利時さらに20）。敗北でも参加EXPを得る。
- 勝利時のレーティングは+12、敗北時は-8（下限500）。

### 魔法作成・MPコスト

- 魔法は1〜2属性、形状1種、特殊効果1種、威力1〜100で構成する。書庫は最大10個。既存魔法の編集、削除、並べ替えに対応する。
- MPコストは属性コスト合計＋形状コスト＋特殊効果コスト＋`ceil(威力/10)`。最小コストは1。
- 省エネは合計コストを50%にし、端数を切り上げる。登録された2属性シナジーがある場合、さらにコストを6%軽減し、端数を切り上げる（最小1）。
- シナジー威力補正は登録された組み合わせに対し+16〜22%。対象組み合わせと補正値は`src/data.js`を正とする。
- 属性・形状・特殊効果ごとの個別コストも`src/data.js`を正とする。ガイドの表とコードに差異が見つかった場合は、リリース前に解消して両方を一致させる。

### バトル・CPU

- 各戦闘の開始時にプレイヤーHP・MPを最大値まで回復する（Ver.0.3の挙動を継承）。CPU HPは`100 + 難易度 × 14`、CPU MP上限は`70 + 難易度 × 5`。CPUは10段階から選択する。
- CPUレベルは`max(1, プレイヤーレベル + 難易度 - 1)`。CPU MP回復は`5 + floor(難易度/4)`。
- 戦闘は3レーン、プレイヤーの1ターン1行動、15秒制限。時間切れはパスと同じターン終了。各ターン後に状態異常・継続効果を処理し、双方のMPを回復して次ターンへ進む。
- 命中は形状のレーン規則、特殊効果、位置で判定する。追尾・貫通爆発はレーンを越えて命中し、爆発は異なるレーンへの攻撃威力を22%下げる。
- クリティカルは28%で威力1.75倍。高速詠唱は威力1.12倍、貫通・分裂・連鎖は1.14倍、貫通爆発は1.22倍。ランダム効果は威力0.72〜1.28倍。
- 炎・毒・氷・雷・草・闇・水・風・ロボ属性は、個別確率で対応する状態異常を試みる。光属性の魔法は使用者の状態異常を解除する。
- 火傷は毎ターン最大HPの5%、毒は4%のダメージ。凍結は50%、麻痺は35%で行動失敗。暗闇は攻撃を40%の確率で外す。呪いは与ダメージを20%低下、被ダメージを12%増加。睡眠は行動不能で、攻撃を受けると解除。拘束は移動を禁止、沈黙は魔法を禁止、混乱は狙いレーンをランダムにする。
- 状態異常は最大3種。同一状態異常の再付与は残りターンを更新し、4種目は最古の状態異常を置き換える。
- 属性ごとの正確な状態異常確率、持続ターン、CPU行動選択率、その他コスト表は`src/data.js`および`src/battle.js`の値を正とする。

### 将来要件：管理者専用画面

- 管理画面は将来の運営機能として必須要件に記録するが、Ver.1.0では実装しない。
- 実装時はサーバー側の認証・認可を必須とする。管理者アカウントと追加認証、短い有効期限のセッション、ログイン試行制限、操作監査ログを用意する。
- 画面を隠す、URLを秘密にする、クライアント側にパスワードを置く、ブラウザーだけで権限判定する方式は認証として認めない。管理用APIも各リクエストでサーバー側権限を確認する。
- 実サーバーの認証基盤・安全な管理者権限保管が整うまで管理画面や管理APIは追加しない。
- 現時点で管理画面のURLは発行しない。GitHub Pagesは静的サイトであり、URLにアクセス制限を加えるだけでは管理者認証にならないため、サーバー側認証を実装できる構成になるまで公開しない。

### 運用・保全

- Ver.0.3.1を基準ブランチとして保持し、Ver.1.0は別リリースブランチ・タグで公開する。
- 既存機能や仕様を取り除く場合は、本記録と変更履歴に理由および代替を明示する。既存セーブ読込に失敗した場合は壊れたデータのバックアップを試み、新しい進行状況でプレイを継続可能にする。
